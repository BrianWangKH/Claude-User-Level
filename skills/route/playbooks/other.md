# Playbook: other (no row fits)

For a request none of rows 1–11 fits. Each use is logged, so the requests that keep landing here can become their own row and playbook later; the person decides which, when planning.

1. Before anything else, say in one line which row came closest and why it doesn't fit. If one fits after all, switch to it.
2. Work by the main session's rules (「與使用者互動」): goal, root cause, approach and its first risk-free step first; long work goes to a background subagent with a written spec; approval by risk.
3. At the end, append one line to `plans/route-misses.md` of the current repo (Write/Edit tool; create the file with a header line if missing): `| <date> | <the kind of request, a few words> | <closest row and why not> | <the steps actually taken> |`. Outside a repo, say the line in the reply instead.
4. When the same kind shows up there a third time, mention it once to the person as a candidate row (situation, where it runs, the steps that worked); don't add it yourself.
